# pg-pr retirement preconditions

Retirement-precondition content authored by phase 5 (`pg2-2j5ac.23`) of the unified connector
architecture design; see
`docs/superpowers/specs/2026-09-03-unified-connector-architecture-design.md`'s "What moves where"
and "Migration-window policy" sections for the full narrative this page transcribes decisions
from.

This page is a **map, not a migration**: everything below is already decided in the design of
record, but (per this set's own [Extent (out)](README.md#scope-extent--floor)) the actual
retirement code — the cutover of any command group, the SQLite disposition execution, the tools
that do the migrating — remains out of this set's scope until each destination ships. This page
exists so a later phase building one of those destinations has one place to cite when it extends
this set further, per the [README](README.md)'s own "a packet that builds any of these MUST
extend this set in the same change" rule.

## Per-table SQLite disposition

pg-pr's SQLite store holds several tables. The design of record's "Migration-window policy"
section, as amended 2026-09-09 (pg-desk design, its section 9.3), states a final disposition for
every one of them:

> **Amended 2026-09-09 (pg-desk design, its section 9.3).** The per-table dispositions are now
> complete, and the feedback exception above is moot. `feedback` and `code_comment_message` DROP:
> dispositions are re-derived by `pg-desk`'s interpreter each run (Phase 3 migrated zero real
> rows), so no disposition store migrates under any backend and the same-cutover-step obligation
> has nothing left to bind. `pull_request`, `pr_revision`, and `pr_approval` DROP, re-derived into
> `pg-desk`'s `entity` and `interpretation` tables on the first sweep, with revision history an
> accepted loss; only `pull_request`'s `user_hidden`, `user_hidden_reason`, and `wip` columns
> migrate, through `pg-desk import-pg-pr-annotations`, into `pg-desk`'s `annotation` table, which
> is the client/dashboard layer the `user_state` bullet above left unnamed. `outbox`,
> `repo_sync_state`, and `data_migration` drop as decided. `store.db` itself is deleted only with
> the `packages/pg-pr` module: the phase 11 flip disables the daemon and leaves the file and the
> command groups, and phase 12 deletes the retiring command groups and still leaves the file.

Summarized per table:

| Table                                                     | Disposition                                                                                                                                                                       |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `feedback`, `code_comment_message`                        | DROP — re-derived by `pg-desk`'s interpreter each run                                                                                                                             |
| `pull_request`, `pr_revision`, `pr_approval`              | DROP — re-derived into `pg-desk`'s `entity`/`interpretation` tables; revision history is an accepted loss                                                                         |
| `pull_request.user_hidden`, `.user_hidden_reason`, `.wip` | MIGRATE — via a future `pg-desk import-pg-pr-annotations` tool, into `pg-desk`'s `annotation` table                                                                               |
| `outbox`, `repo_sync_state`, `data_migration`             | DROP                                                                                                                                                                              |
| `store.db` (the file itself)                              | Deleted only with the `packages/pg-pr` module — the phase 11 flip disables the daemon and leaves the file; phase 12 deletes the retiring command groups and still leaves the file |

## Executed vs. decided-but-not-yet-executed

**Only one of the dispositions above has actually run.** Phase 3 (`pg2-2j5ac.19`) already EXECUTED
the feedback-disposition table's own cutover — its close reason states: "migrated 0 real
dispositions... left the underlying SQLite table/`ListFeedback` intact for `pr_view` and full
retirement in Phase 5."

Every other table's disposition documented above — `pull_request`, `pr_revision`, `pr_approval`,
the `pull_request` annotation-column migration, `outbox`, `repo_sync_state`, `data_migration`, and
`store.db` itself — is **decided, but not yet executed**. Execution is a future phase's or
packet's job, gated on each disposition's own named destination actually shipping (`pg-desk`'s
`entity`/`interpretation`/`annotation` tables and the `import-pg-pr-annotations` tool, none of
which exist yet). This page records the decision; it builds none of that code.
