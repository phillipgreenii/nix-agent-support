# pg-pr process feedback

Lifecycle handler for processing-cycle / feedback / action beads. The
beads themselves land in Phase 3 (epic `beads_pg2-ywy`); this skill is
prepped so it's ready when the surface is live.

## Bead shapes

- **processing-cycle** — parent bead created by `pg-pr sync` when new
  feedback is detected on a merge-request. Children are
  feedback/action beads.
- **feedback** — one upstream review comment or thread. Carries
  `repo`, `pr`, `thread_id`, `author`, `author_role`, `path`, `line`.
- **action** — proposed change in response to a feedback (e.g.,
  "rename foo", "add test", "ignore"). Generated by the agent and
  reviewed by the human.

## Workflow

1. Claim the processing-cycle bead:

   ```bash
   bd update <processing-cycle-id> --claim
   ```

2. List its children:

   ```bash
   bd children <processing-cycle-id>
   ```

3. For each feedback bead:
   1. Read upstream context: `pg-pr pr show`, `pg-pr pr files`, etc.
   2. Decide one of:
      - Implement the change (create a small commit).
      - Push back with a reply: `pg-pr comment respond <feedback-id>`
        (Phase 3).
      - Mark resolved if the conversation is done:
        `pg-pr comment resolve <thread-id>` (Phase 3).
   3. Close the feedback bead:
      ```bash
      bd close <feedback-id> --reason="<short verb-phrase>"
      ```

4. Close the processing-cycle bead with a one-line summary.

## Boundaries

- The processing-cycle bead is the unit of work. Never close it before
  every child has been closed.
- Author precedence on responses: `self > team_member > org_member > bot`.
- Don't strip the 🤖 marker — `pg-pr comment` adds it automatically.
