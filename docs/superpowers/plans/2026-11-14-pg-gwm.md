# pg-gwm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `pg-checkout-pool` into `pg-gwm`, the generic git worktree manager of the behavior set, and move the ccpool router handler onto it so the handler no longer creates, sweeps or probes worktrees.

**Architecture:** One Go module, `packages/pg-gwm`, holds a CLI (`cmd/pg-gwm`) over an engine (`internal/manager`) that keeps per-repository state in `<git-common-dir>/pg-gwm/` under one flock, runs slow git work outside that lock, and drives git through a provisioner over the shared `cmdrun` seam. A scheduled launchd job runs `pg-gwm reap --all-repos`; an exporter serves metrics read without the lock. The ccpool handler becomes a requester that leases `<role>/<bead>`, renews on its existing supervision tick and releases or expires at session end.

**Tech Stack:** Go 1.26 (`github.com/phillipgreenii/x` `cmdrun`, `cmdruntest`, `gittest`, `gitfixture`, `exitcode`, `pprofserver`; `github.com/BurntSushi/toml` v1.6.0; `golang.org/x/sys`), nix (mkGoApp, mkGoTest, HM and darwin modules), bash + bats for the sibling tools, Grafana alert YAML with promtool tests.

**Spec:** `docs/behavior/pg-gwm/` (README, `lease-interface.md`, `worktree-lifecycle.md`, `failure-modes.md`) and `docs/adr/0126-pg-gwm-owns-managed-worktrees-and-replaces-pg-checkout-pool.md`. Executors read the spec section each task cites; invariant ids (`INV-GWM-n`) are the contract.

## Global Constraints

- Public repo: no organization identifiers in code, tests or docs of `nix-agent-support`; the monorepo's settings live only in `nix-ziprecruiter` (repo `CLAUDE.md`, "Public Repository").
- No bead ids in commits, code, tests or docs (CR-2). Cite rulings by who, when and quoted text.
- Exit codes: shared 1 internal, 2 usage, 4 not-found, 9 busy (from `x/exitcode`); app codes 20 `max-reached`, 21 `name-held`, 22 `branch-in-use`, 23 `dirty`, 24 `lease-released`, 25 `lease-lost`, 26 `ref-unresolvable`, 28 `broken`, 29 `low-disk`; 27 unused; 130 after an interrupt.
- IDs: worktree ids `w-` + 10 lowercase base32 chars, lease ids `l-` + 10; never reused (`INV-GWM-10`).
- JSON: `schema_version` 1; absent values `null`; `metadata` always an object; times RFC 3339 UTC; durations `none` or `<int><s|m|h|d>`.
- Defaults (README table, after decisions 7 and 11): `worktree-root` `<repo dir>.worktrees/`, `worktree-dir-template` `{{repo}}-wt-{{index}}`, `reuse-reclaimed-worktrees` false, `clean-reused-worktree` false, `reuse-hook-policy` `run`, `default-ttl` `none`, `lock-wait` 10s, `git-timeout` 2m, `create-timeout` 30m, `index-lock-stale-after` 10m, `tombstone-retention` 7d; reaper interval 600 seconds.
- Lock reason on every managed worktree: `pg-gwm <worktree id>`. Preserved branches: `pg-gwm/dirty-reaped-<YYYYMMDDTHHMMSSZ>-<branch>-<name or lease id>`, commit subject `adding dirty WIP`.
- Metric label `repo` = the repository's directory name, a hyphen, and the first 6 hex characters of the SHA-256 of its common git directory (two clones with one name never share a series).
- Go test runs by agents: `nice -n 10 go test -p 4 ...` with a private `GOCACHE="${TMPDIR:-/tmp}/go-build-<session-id>"` (L-4, L-5). Nix checks build in the background (`bgrun` + `bgwait --timeout 540`, Bash timeout 600000).
- Unit tests use real git through `x/gittest` and the hermetic helper of task 2; no raw `exec.Command("git")` in tests; every test sets `XDG_STATE_HOME` and `XDG_CONFIG_HOME` to temp directories. A test that spawns or kills a second process carries the build tag `integration` and runs only in its own check (V-4).
- Behavior docs change in the same commit as the behavior they describe, and a task that delivers a realization-gap row removes that row from `docs/behavior/pg-gwm/README.md` in the same commit. Row owners: `INV-GWM-28` task 4; `INV-GWM-15` task 5; `INV-GWM-5` task 6; `INV-GWM-24` task 8; `INTF-GWM-CLI`, `INV-GWM-11` and `INV-GWM-20` task 9 (the last subcommand and the reap rules); `INV-GWM-32` task 11; `Consumers` task 14; `INV-GWM-26` narrowed by task 15 and removed by task 17.

## Decisions This Plan Takes

The spec leaves these open or inconsistent. The plan decides them so tasks are unambiguous; each is written into the spec by the task named. None contradicts an operator ruling quoted in the README.

1. **Names compare case-insensitively.** The glossary and the review's scenario 5 say case-insensitive; `INV-GWM-5` says "compared exactly". macOS refs on a case-insensitive volume collide. Task 4 edits `INV-GWM-5`.
2. **SIGTERM, then SIGKILL after a 30-second grace.** `INV-GWM-31` says never SIGKILL, but a bounded runner must eventually reap a git that ignores SIGTERM. A git killed that way leaves its worktree `broken`. Task 2 edits `INV-GWM-31`.
3. **The copy-on-write `Clone` provisioner, the lsof-based daemon counter, the old slot alerts and the handler's unused `checkout-pool` isolation type are deleted.** Nothing uses them; `INV-GWM-15` covers a CoW store "when one exists". Task 1.
4. **`lease --or-renew` ignores branch arguments when it renews**, reports `"renewed": true`, and warns on stderr naming the worktree's current branch. Task 7 adds this to `INV-GWM-7`.
5. **The handler's worktree lease has its own TTL**, `worktreeLeaseTTL` (default `30m`). The handler checks it on the existing supervision tick (every `LeaseTTL / 4`, 30 seconds at the 2-minute default) and renews only when less than half the TTL remains, so a session renews about every 15 minutes (10 sessions × 4 an hour × 168 hours = 6,720 renew events a week, about 2 MB at 300 bytes each). A dispatch that returns while its session still lives (a parked `needs_input` session) renews with `parkedTTL` (default `3d`); the janitor's orphan pass renews the worktree lease of every orphan it leaves running. `OQ-GWM-TTL-REMOVE` forbids dropping the expiry. Task 14.
6. **Old per-bead worktrees drain out before the sweep code goes.** pg-gwm worktrees live under their own `worktree-root` (task 13), not the handler's worktree directory, and carry a git lock the old sweep already skips. A write lease that meets `branch-in-use` from an old-style `<worktree dir>/<bead>` worktree is a busy decline: a live holder means the bead is being worked, and the old sweep clears a dead one within a janitor cycle. Task 17 deletes the sweep, the leftover reclaim, the lsof probe and the `remove-worktree` subcommand after a post-deploy check finds no old-style worktree left.
7. **Configuration file:** `$XDG_CONFIG_HOME/pg-gwm/config.toml`, one table per repository keyed by the main checkout's real path (`filepath.EvalSymlinks`): `[repos."/abs/path"]` with the README keys verbatim. The per-repository `reap-interval` key becomes the reaper's own setting (`reaper.intervalSeconds`, default 600): one machine runs one reaper, so a per-repository interval serves no story. Task 11 moves the key out of the README's per-repository table and keeps `INV-GWM-32`'s "every `reap-interval`" true. **Operator may overrule.**
8. **Templates are Go `text/template` with zero-argument functions** `repo`, `index`, `name`, `lease_id`, `owner`, `min`, `max`, `count`, plus `metadata "key"` and the pipe function `letter` (0 → `a`, 25 → `z`, 26 → `aa`), so `{{repo}}-wt-{{index}}` and `slot-{{index | letter}}` render as the README shows.
9. **The preservation commit's undo instructions use a branch of the requester's own**: `pg-gwm lease -b <your-branch> <preserved branch>`, then `git reset --soft HEAD~1`. Leasing the `pg-gwm/` branch itself would leave the person on a branch `preserved prune` will not delete. Task 8 edits `INV-GWM-24` and `JOURNEY-GWM-DIRTY-EXPIRED` step 4.
10. **The agent skill does not change the always-on R-4 worktree rule.** It tells agents to lease from pg-gwm when they need a single-repo worktree outside a workforest set in a configured repository; changing R-4 itself is the operator's call (flagged in task 16).
11. **No standby branches.** `standby-branch-template` and `standby-base` are dropped: a kept worktree goes detached, as the old pool's slots did, and no story, ruling or deployment needs a named standby. Task 3 edits the README config table, `INV-GWM-22` and `INV-GWM-23`. **Operator may overrule.**
12. **The max-reached alert rate is a literal in the rule file** (5 an hour). `INV-GWM-33` asks for "a configured rate"; the rule file is the configuration, and changing it is a one-line edit. Task 10 says so in `INV-GWM-33`. **Operator may overrule.**

## Review Focus

1. **Symlinked or relative repository paths** (macOS `/var` → `/private/var`, a repo reached through `/Volumes`). A person expects config and the reaper registry to find the repo however they typed the path. Test in task 3.
2. **The first lease in an unconfigured repository**, whose `<repo dir>.worktrees/` does not exist yet. A person expects it to work like `git worktree add`. Test in task 6.
3. **Ctrl-C during a slow creation.** A person expects the half-made worktree to be dealt with, not left `preparing`. Test in task 6.
4. **A name that cannot become a branch beside existing refs** (row 8 with name `worker` while `worker/bd-1` exists). A person expects `usage` with git's message, not exit 1. Test in task 6.
5. **A refusal under `cd "$(pg-gwm lease … --print=path)"`.** A person expects the `cd` to fail, not to receive JSON or an empty string and stay in the main checkout. Test in task 6.

    1. Single-flight on `Dir/reap.lock` (held → `skipped`).
    2. `worktree-root` missing → `unreachable`, a warning, no change (`INV-GWM-30`).

    5. Every `Broken` is retried once per reap (preserve, then remove); a failure keeps its directory and is recorded in an event.
    6. Every `released` and `lease-expired` worktree reclaimed (`INV-GWM-23`): kept detached as `available` up to `min` with reuse on, otherwise removed (unlock, `StopFSMonitor`, remove; branch kept).
    7. Every `available` worktree checked for unsaved work; `available` worktrees above `max` removed.
    8. Standbys created one at a time (`Creating`, under `HoldCreate`) until `min` or the floor; reaching the floor adds a warning and a `low-disk` event.
